# Готовность dialekt для пилота IBA

**Версия dialekt:** v0.11.1 production, v0.20.0 RC (MCP UI)
**Дата отчёта:** 2026-04-27
**Источники:** `AGENT_CATALOG.md`, `CAPABILITIES_INVENTORY.md`, `TOOLS_AVAILABLE_TODAY.md`, `python/server.py`, `dialekt_manifest.schema`

> Цель этого отчёта — честно сказать какие задачи IBA закрываются текущей версией dialekt без написания нового кода, какие требуют настройки на стороне IBA, и какие нужно отложить до M2.

## Детальный анализ каждой задачи

### Задача 1 — Резюме тренеров

**Статус:** ✅ Работает сейчас
**Как:** Pure-LLM агент (без подключений). System prompt описывает структуру резюме на сайте IBA, тон («продающий, без искажения фактов»), запрещённые правки (даты, места работы, ФИО). Источник CV пользователь либо вставляет в чат, либо загружает через `/upload` (контент инжектится в контекст следующего хода).
**Что нужно настроить:**
1. От IBA: 3-5 эталонных опубликованных резюме с сайта + 3-5 «сырых» исходников от тренеров → составить few-shot примеры в system prompt.
2. От IBA: чек-лист правил — какие поля обязательны, что нельзя менять, как форматировать опыт/регалии/сертификаты.
3. Создать manifest `agents/iba/content_editor.yaml` (см. ниже).
**Ограничения:**
- gemma3-12b иногда вставляет английские слова в русский текст (catalog 4.2). Митигация: явное правило в system prompt + финальный человеческий проход. Для критично важных резюме рекомендую `autonomy: review-only` (оператор IBA видит черновик, апрувит).
**Время настройки:** 30 минут после получения эталонов.

### Задача 2 — Программы обучения

**Статус:** ✅ Работает сейчас
**Как:** Тот же агент `content_editor`, расширенный шаблоном для программ (превью, цели, аудитория, программа по дням, цена). Различение «резюме vs программа» — по типу запроса в чате (либо отдельный агент-близнец `program_editor` если нужно изолировать промпты).
**Что нужно настроить:** То же что и (1), но эталоны программ.
**Ограничения:** Те же. Объём программы может выйти за токен-бюджет gemma3-12b — для длинных описаний переключиться на gemma3:27b или итеративно собирать блоки.
**Время настройки:** 30 минут.

### Задача 3 — Работа с сайтом

**Статус:** ⚠️ Частично — зависит от стека сайта IBA
**Как (возможные пути):**
- **Если сайт на CMS с REST API (WordPress, Strapi, etc.):** агент с capability `network`, system prompt содержит endpoint + токен, агент вызывает API через `httpx` из Python. Работает, но это кастомная интеграция под IBA.
- **Если сайт сидит на Postgres/MySQL:** дать агенту readonly + (опционально) write подключение к БД сайта. dialekt SQL-агенты отлично с этим работают (catalog 1.1, 1.2). Для записи — `database_write` capability + `autonomy: ask-before-write`.
- **Если сайт статический в git-репо:** filesystem MCP сервер (`@modelcontextprotocol/server-filesystem`) направить на путь к репо, плюс git через shell. Это путь через MCP UI v0.20.0 RC.
**Ограничения:**
- Нет встроенного веб-краулера — для «найти устаревшие страницы» нужен либо sitemap.xml + httpx, либо доступ к БД CMS.
- В UI dialekt нет формы для http-api connections (только postgres/mysql/clickhouse) — `connection.type: http-api` валидируется схемой, но рантайма нет (`CAPABILITIES_INVENTORY.md §3`). Поэтому HTTP API сайта вызывается через Python `httpx`, а не через connection.
**Время настройки:** 1-3 дня после уточнения стека сайта (см. вопросы ниже).

### Задача 4 — Даты программ

**Статус:** ✅ Работает сейчас
**Как:** Агент `schedule_planner`, model `qwen2.5-coder:7b` (хорошо генерирует Python). System prompt:
- список государственных праздников РК на год (зашить как константу — обновлять раз в год вручную);
- правила (3 очно + 3 онлайн, будни, не пересекать праздники, равномерно по году);
- инструкция: «вычисляй календарь через Python — `datetime`, `calendar` — не угадывай даты».
Агент генерирует Python код, OI исполняет, результат — markdown-таблица 300 строк. На выходе — экспорт в CSV/JSON через `filesystem_write`.
**Что нужно настроить:**
1. От IBA: точный список 300 программ (имя, формат очно/онлайн, длительность, тип — есть ли привязка к сезону).
2. От IBA: подтверждённый список праздников РК 2026/2027 (мы возьмём официальный календарь, IBA подтвердит).
3. Опционально: ограничения по аудиториям/тренерам, если они конкурируют за слоты.
**Ограничения:**
- Cron / автозапуск — ❌. Этот агент работает только интерактивно («сгенерируй расписание на 2027 год» → агент делает на месте). Для пересчёта раз в квартал — оператор IBA дёргает его сам.
- Если 300 программ конкурируют за тренеров/залы, появляется constraint-satisfaction задача — LLM с этим справляется хуже чем CSP-солвер. Если у IBA сложные ограничения, готовый код Python внутри агента (или внешний скрипт) надёжнее, чем «попроси LLM пересобрать».
**Время настройки:** 1 день.

### Задача 5 — Аналитика сайта

**Статус:** ⚠️ Частично
**Как:**
- **Точечно (вручную):** оператор IBA копирует HTML/текст страницы в чат, агент анализирует — устарела ли, есть ли продающий блок, что добавить. Pure-LLM, ✅ работает сейчас тем же `content_editor`.
- **Систематически (обход всех страниц):** требуется доступ к сайту (см. №3). Когда доступ есть, агент через Python обходит sitemap, складывает выводы в отчёт.
**Ограничения:** Без программного доступа к сайту это превращается в ручной процесс — оператор по одной странице. На 300 программ это ~2-3 дня работы оператора.
**Время настройки:** 0 минут для ручного режима; зависит от №3 для автоматического.

### Задача 6 — Законодательство РК

**Статус:** ❌ автоматический мониторинг / ⚠️ ad-hoc анализ
**Как:**
- **Мониторинг изменений (адилет.zan.kz и т.д.) с уведомлениями:** ❌ Не работает в v0.20.0. Нужны: (а) scheduled trigger — нет в рантайме (`CAPABILITIES_INVENTORY.md §4`), (б) web-search/fetch адаптер — ❌ нет (`TOOLS_AVAILABLE_TODAY.md`). Roadmap M2 (Q3 2026).
- **Ad-hoc анализ:** оператор IBA вставляет текст закона/изменения в чат → агент предлагает темы тренингов, целевую аудиторию, форматы. ✅ Pure-LLM работает.
**Ограничения:** Без cron + web-search оператор должен сам отслеживать изменения. dialekt помогает только когда текст уже в руках.
**Что честно сказать клиенту:** «Автоматический мониторинг — Q3 2026. Сейчас даём ad-hoc-анализ: вы скидываете в чат текст изменения, агент за 30 секунд предлагает 3-5 тренинговых тем».
**Время настройки:** 30 минут (включить как режим в `smm_manager` или сделать отдельный `legal_analyst`).

### Задача 7 — Instagram и новости

**Статус:** ⚠️ Частично — копирайт ✅, автопубликация ❌
**Как:**
- **Тексты постов, анонсов, расписания, регистрации:** ✅ Pure-LLM. Агент `smm_manager`, model gemma3:27b/12b, language `ru`, system prompt с tone-of-voice IBA + примерами хороших постов.
- **Публикация в Instagram:** ❌ Нет встроенной интеграции. На сервере dias стоит Instagram MCP (`ig.dias.now`, port 18744), но он *не валидирован* на E2E через dialekt MCP UI — добавлять как pilot-feature рискованно. Для пилота: ручной copy-paste из dialekt в IG.
**Ограничения:**
- Нельзя запланировать публикацию (нет scheduler).
- Нельзя анализировать engagement постов (нет IG-аналитики).
**Что честно сказать клиенту:** «Тексты пишем — оператор копирует в IG. Автопубликация — позже, когда сделаем кастомную интеграцию IG MCP под ваш аккаунт (отдельный SOW)».
**Время настройки:** 30 минут на копирайт-агент.

### Задача 8 — Фото и визуал

**Статус:** ⚠️ Частично — зависит от железа IBA
**Как:**
- **Генерация баннеров/визуалов под пост:** dialekt умеет вызывать локальный ComfyUI через `POST /comfy/txt2img` (Flux Schnell, 10-30s/изображение, GPU обязателен). ✅ если на машине пилота есть GPU 8GB+ VRAM и установлен ComfyUI; иначе ❌ (timeout). На сервере dias ComfyUI работает — но если IBA развернёт dialekt у себя, у них своего GPU может не быть.
- **Анализ существующих фото (vision):** ❌ нет vision-модели в установленных Ollama (`qwen2.5-coder:7b, gemma3-12b, gemma2:2b, nomic-embed-text`). Roadmap M2.
**Ограничения:**
- Бренд-стиль IBA → нужен LoRA / референсные изображения, что выходит за рамки 2-недельного пилота.
- Если нет GPU — единственный путь это внешний сервис (Midjourney, DALL-E), что требует API-интеграции (тоже за рамками пилота).
**Что честно сказать клиенту:** «Генерация изображений требует GPU; если у вас есть машина с RTX 3060+ — настроим ComfyUI и подключим. Если нет — это отложим, либо подключим внешний платный сервис отдельным SOW».
**Время настройки:** 0 минут если ComfyUI уже стоит; 1 день если нужно поднять с нуля.

## Что запускаем в первые 2 недели

3 агента, каждый с полным manifest YAML в `agents/iba/`:

1. **`content_editor`** (`agents/iba/content_editor.yaml`) — закрывает задачи 1, 2, 5 (ручной режим), 6 (ad-hoc).
   - Pure-LLM, gemma3-12b, language `ru`, autonomy `review-only`.
   - Принимает: вставленный текст или загруженный файл (CV/программа/HTML страницы/текст закона).
   - Выдаёт: переписанный текст под формат IBA либо аналитику с пунктами «что обновить».

2. **`schedule_planner`** (`agents/iba/schedule_planner.yaml`) — закрывает задачу 4.
   - qwen2.5-coder:7b, language `multi`, capability `filesystem_write` (для экспорта CSV/JSON), autonomy `ask-before-write`.
   - Считает календарь через Python внутри OI, отдаёт markdown-таблицу + опционально CSV.

3. **`smm_manager`** (`agents/iba/smm_manager.yaml`) — закрывает задачу 7 (копирайт).
   - gemma3:27b → gemma3-12b acceptable, language `ru`, autonomy `review-only`.
   - Жанры: пост-анонс, расписание, регистрационный текст, новости. По запросу — варианты под Instagram/Telegram/email.

## Что честно сказать клиенту «не сейчас»

- **Автоматический мониторинг законодательства РК (задача 6).** Нет cron, нет web-search. Roadmap M2 (Q3 2026). Workaround: ad-hoc анализ присланного текста.
- **Автопубликация в Instagram (задача 7).** Нет валидированной IG-интеграции в dialekt UI. Если IBA критично — отдельный SOW на кастомную MCP-интеграцию (не пилот).
- **Анализ существующих фото / vision (задача 8).** Нет vision-модели. Roadmap M2.
- **Генерация изображений (задача 8) без локального GPU.** Если у IBA нет GPU — переносится в отдельный SOW (внешний платный API типа Midjourney).
- **Систематический обход сайта IBA (задачи 3, 5).** Зависит от стека сайта — не делаем «вслепую». См. вопросы к IBA ниже.

## Технические требования от IBA

Что нужно узнать до старта пилота:

1. **Стек сайта IBA.** WordPress / Tilda / Bitrix / самописный / статика? Какой CMS?
2. **Доступ к сайту.** Есть ли REST API + админский токен? Можем ли получить readonly доступ к БД сайта? Если git-репо — есть ли SSH/деплой через CI?
3. **Эталоны контента.** 5 опубликованных резюме + 5 опубликованных программ с сайта (как пример «золотого стандарта»). Плюс 3-5 сырых исходников (как тренеры присылают сейчас).
4. **Tone-of-voice + стилистика.** Есть ли brand-book / инструкция редакции? Если нет — соберём с одной встречи с маркетологом IBA.
5. **Список 300 программ.** Имя, формат (очно/онлайн), длительность в днях, есть ли сезонные ограничения (например, «школьные программы только в сентябре-мае»). CSV/Excel сойдёт.
6. **Праздники РК.** Подтверждение календаря на 2026-2027 от IBA (учитывая корпоративные «дополнительные» дни если такие есть).
7. **Instagram.** Аккаунт, доступы (для будущей интеграции), 10 примеров «удачных» прошлых постов.
8. **Фото/GPU.** Есть ли у IBA сервер/машина с GPU? Если планируется генерация — какой объём в неделю?
9. **Кто оператор.** Один человек на стороне IBA, который ежедневно работает с dialekt — кто это, какой технический уровень (пишет Python? только UI?).

## Риски пилота

1. **Зависимость задач 3 и 5 от стека сайта.** Если IBA не даст программный доступ к сайту в течение 1-й недели — задачи 3 и 5 переходят в ручной режим, ценность пилота падает. *Митигация:* сразу на discovery-call в первый день договариваемся про CMS/DB-доступ; если не получаем — публично откатываемся к «тексты пишем, публикует оператор».
2. **Качество русского у gemma3-12b.** Catalog 4.2 фиксирует утечки английских слов. *Митигация:* `autonomy: review-only` на `content_editor` и `smm_manager` — оператор IBA проходит каждый черновик до публикации; параллельно тестируем gemma3:27b если хватает VRAM на машине пилота.
3. **300 программ × constraint-satisfaction в задаче 4.** Если у IBA сложные ограничения (тренеры, залы, последовательности модулей), LLM-генерация календаря даст плохое качество. *Митигация:* пишем явный Python-солвер внутри агента (constraint propagation), LLM только формулирует и интерпретирует. Если конструктив сложнее — отдельный модуль (за рамками пилота).
4. **Отсутствие vision блокирует задачу 8.** *Митигация:* честно сказали клиенту на discovery-колле; дать им самим выбрать «делаем без visualов» или «отложим IG-визуалы».
5. **gemma3-12b или 27b не запускается на машине пилота.** Если у IBA нет 16GB VRAM — пилот пересобирается на cloud-tenant dialekt-cloud. *Митигация:* в первый день проверяем `GET /system` на их машине, фиксируем модель.
6. **MCP UI ещё не релизнут (v0.20.0 в RC).** Если пилот стартует до выхода v0.20.0 — ставим v0.11.1, MCP-блок откладываем (на пилоте IBA он не критичен — никакой из 3 агентов его не требует). *Митигация:* стартуем на v0.11.1, апгрейдим в середине пилота безболезненно.

## Вердикт для Диаса

**Можно запускать пилот IBA прямо сейчас:** ДА — но в скоупе 3 агента (`content_editor`, `schedule_planner`, `smm_manager`) и 4-5 из 8 заявленных задач.

**Задачи которые закроем в первые 2 недели:**
- ✅ Задача 1 (резюме тренеров)
- ✅ Задача 2 (программы)
- ✅ Задача 4 (расписание дат)
- ✅ Задача 7 в части копирайта (IG/новости — тексты)
- ⚠️ Задача 5 в ручном режиме (вставка страницы → анализ)
- ⚠️ Задача 6 в ad-hoc режиме (вставка закона → темы)

**Задачи которые честно defer'им:**
- Задача 3 (CRUD сайта) — старт после получения CMS-доступа от IBA, иначе ручной режим
- Задача 6 в части автоматического мониторинга — M2
- Задача 7 в части автопубликации в IG — отдельный SOW
- Задача 8 (визуал) — зависит от GPU; иначе отдельный SOW

**Главный риск:** IBA рассчитывает что dialekt «делает всё за оператора», а реально это co-pilot для редактора — оператор остаётся в петле на review. *Если на discovery-колле этого не проговорить — пилот закончится разочарованием.* Прямо сказать: «dialekt экономит 70% времени редактора, но редактор обязан остаться».

**Первое что нужно получить от IBA:**
1. Стек сайта (WordPress / Tilda / Bitrix / etc.) и формат доступа.
2. 5 эталонных резюме + 5 эталонных программ с сайта (как «золотой стандарт»).
3. Подтверждение что есть машина с 16GB+ RAM, желательно GPU 8GB+ (для gemma3:27b и опционально ComfyUI).

Без пунктов 1 и 2 пилот не стартует — это блокеры для настройки `content_editor` и любых задач сайтового CRUD.
